좋아요, “실전에서 먹히는 선물 자동봇”을 목표로 **무엇을 우선 설계·튜닝**하고, **어떤 기준으로 검증**할지를 단계별로 정리해 드릴게요.
핵심은 **승률 집착 X → 기대값(Expectancy)·리스크·실행 안정성에 집중**입니다.

---

# 1) 우선순위 로드맵 (P0→P2)

## P0. 필수 안정성(돈 잃지 않는 뼈대)

1. **리스크/포지션 사이징**

* 1트레이드당 계정 리스크: `0.25% ~ 0.75%` (초기), 최대 `1.0%` 이하
* 동시 포지션 수 제한: `1~3개` (상관성 고려)
* **계단형/ATR 기반 SL**: 손절 “가격”이 아닌 “위험액(%)”을 먼저 세팅 → 진입 수량이 자동 조정되게
* **레버리지 상한**: 변동성×레버리지×SL거리로 **청산가 여유 3~5×SL** 확보

2. **수수료·슬리피지·펀딩 완전 반영**

* taker 기준 수수료 가정(+펀딩 수지): 백테스트·페이퍼 모두 반영
* 슬리피지: 변동성·체결가깃값·유동성(오더북 깊이)의 함수로 보수적으로 모델링

3. **중앙집중화된 리스크 스위치**

* **일일 손실 한도(DDL)**: -2%~-3% 도달 시 당일 종료
* **연속 손실 스톱**: 3~4연속 SL 시 전략 쿨다운
* **포지션 네팅 규칙**: 역포지션 금지/헤지 모드 사용 여부 명시

> ✅ P0 완료 기준: ① 기대값 계산에 수수료/슬리피지/펀딩 반영, ② 1트레이드 리스크와 DDL 작동 로그 확인, ③ 청산가 여유 자동 검증.

---

## P1. 성과 엔진(돈을 버는 구조)

1. **손익비 구조 최적화 (R:R 튜닝이 1순위)**

* 진입은 보수적, **익절은 구간 분할(TP1/TP2/Trail)**
* **TP/SL 비율 목표**: `≥ 1:1.5` (스윙/추세), 스캘핑은 `≥ 1:1` + 높은 승률
* **트레일링 방식**: ATR×k, 최근 n봉 저/고 갱신, BE(손익분기 이동) 조건 등 A/B 테스트

2. **시그널 클린업**

* **필터**: 추세(HTF MA/AVWAP), 변동성(ATR/비정상 폭발), 거래량(OBV/Volume Spike), 시간대(세션)
* **피해야 할 구간**: 펌핑·뉴스 급등락, 유동성 얕은 시간, 이벤트 전후 N분 블랙아웃

3. **시장 레짐(상태) 인식**

* 레인지 vs 트렌드, 저/고 변동성, 강세/약세 레짐을 정량 지표로 태깅
* 레짐별 **파라미터 프리셋**(SL거리, TP구간, 필터 엄격도) 자동 전환

> ✅ P1 완료 기준: ① OOS 기준 **Expectancy ≥ 0.1R**, ② 레짐별 성과 편차 안정화, ③ TP/SL/Trail 조합이 재현성 있게 우위.

---

## P2. 실행·운영 신뢰성(돈이 지켜지는 운영)

1. **주문 실행 안정화**

* 재시도 로직, 부분 체결 처리, 잔량/약정 누락 보정
* 파동장 세이프티(체결 실패 시 슬리피지 캡·재진입 금지 쿨다운)

2. **상관성/익스포저 컨트롤**

* 심볼 상관 네트워크로 **동시 위험 한도** 묶음 관리
* 펀딩 편향(롱/숏 쏠림) 시 델타 중립화 옵션

3. **모니터링 & 리커버리**

* 실시간 PnL·노출·자본곡선 경고, API 에러/지연 감지
* 봇 재시작 안전 재동기(오픈 포지션/주문 스냅샷 → 상태 복원)

> ✅ P2 완료 기준: ① 주문/상태 일치율 100%에 수렴, ② 이상체결·재연결 이벤트에도 포지션 손실 억제, ③ 운영 알림 SLA 준수.

# 2) 지표·목표치(실전 벤치마크)

| 구분                | 목표 (OOS 기준)            | 메모                          |
| ----------------- | ---------------------- | --------------------------- |
| Expectancy        | **≥ +0.10 R/trade**    | 수수료/슬리피지/펀딩 포함              |
| 승률 × 손익비          | 2.0~2.5 이상             | 예: 승률 50% × 손익비 1:1.8 ≈ 2.4 |
| MDD               | **≤ -12%** (초기 ≤ -20%) | DDL/쿨다운으로 제어                |
| Calmar (CAGR/MDD) | ≥ 0.7 (초기 ≥ 0.4)       | 연복리/최대낙폭                    |
| Sharpe (일간)       | ≥ 1.2                  | 수익/변동성                      |
| Ulcer Index       | 낮을수록 좋음                | 자본곡선 스트레스                   |
| 연속손실 Max          | 6 이하(목표 4~5)           | 리스크 상한 튜닝                   |
| 체결 슬리피지           | 백테 대비 페이퍼 +α% 제한       | 유동성 시간대 선택                  |

# 3) 백테스트 → 페이퍼 → (소액)라이브 프로토콜

## 데이터 & 샘플링

* **체결데이터**: 1m 이상, 체결가 vs 오더북 미스매치 보정
* **커미션**: Taker 수수료 + 평균 펀딩 = **견딜 수 있게 과다추정**
* **슬리피지 모델**: [k × ATR%] OR [호가 간격 × n] 중 큰 값

## 검증 단계

1. **K-fold 시계열 CV** (확장형 Walk-forward)

   * 6~12 구간 롤링: 훈련→튜닝→OOS 검증
2. **시나리오/레짐 세분화 성과 표**

   * 트렌드·레인지·이벤트·야간/주간·저유동
3. **몬테카를로 리샘플링**

   * 트레이드 순서 섞기 1,000회 → **파산확률/좌측 꼬리** 점검
4. **게이트 조건**

   * OOS Expectancy ≥ 0.1R, MDD ≤ -20%, 연속 SL ≤ 6, 레짐별 기대값 모두 +

> 합격 시 **페이퍼 4~6주**: 실행·슬리피지·재시작 복원·알림 검증
> 통과 시 **소액 라이브**: 리스크 1/3로 시작 → 주차별 승급(DDL 미충족 시 유지)

# 4) 모듈별 “튜닝 노브”(Windsurf에 바로 넘길 항목)

## (A) 시그널

* 엔트리: 돌파/반전/풀백/오더불균형/김프·펀딩 컨트라
* 필터: HTF 추세(1h/4h), ATR 밴드, 세션(런던·뉴욕), 이벤트 블랙아웃
* 하이퍼파라미터: 기간(n), 임계치(k), 중복 진입 쿨다운

## (B) 리스크 & 포지션 사이징

* 위험률 r%/트레이드, 동시 포지션 수, 상관 클러스터 캡
* SL 거리(ATR×k / 구조적 스윙로우/하이), 청산가 여유배수
* 레버리지 상한 (심볼/레짐별 프리셋)

## (C) 익절·청산 로직

* **TP 분할**: 예) TP1= +1R 30%, TP2= +2R 40%, 잔량 트레일
* **트레일링**: ATR×k, 구조적 추세선, BE 이동 조건
* 시간기반 청산(세션 종료, 이벤트 전)

## (D) 실행(Execution)

* 주문 유형: post-only(limit), IOC, market(최소화)
* 재시도 / 부분체결 / 잔량 정리 규칙
* 슬리피지 캡 % + 재진입 금지 쿨다운(s)

## (E) 운영(Ops)

* DDL, 연속 SL 스톱, 주간 손실 한도
* 상태 스냅샷 저장(포지션/주문/지표 캐시)
* 알림: 체결/SL/DDL/재시작/오류

# 6) 실험 설계 & 리포팅(“좋은 프로그램”의 증거)

## 실험 표준(필수)

* **실험명/해시** + **파라미터 스냅샷** + 코드 Git 커밋
* 데이터 기간·심볼·레짐 태깅(트렌드/레인지/저유동)
* 수수료/슬리피지/펀딩 가정 명시

## 최소 리포트 컬럼

* Trades, Win%, Avg Win R, Avg Loss R, **Expectancy(R/trade)**
* PF(Profit Factor), MDD, Calmar, Sharpe, Ulcer, MAR
* Long/Short 분해, 레짐별 성과, 시간대별 성과
* **Monte Carlo 1k의 5/95 퍼센타일 수익**
* 최대 슬리피지 상황 로그(체결 실패/재시도)

## 합격 커트라인(제안)

* OOS Expectancy ≥ 0.10R, PF ≥ 1.3, MDD ≤ -20%, Calmar ≥ 0.5
* 레짐별 기대값 모두 + (한 레짐만 벌고 나머지 -면 보류)

# 7) “튜닝 순서” 체크리스트 (현실 최적 루트)

1. **SL/리스크 먼저 고정** (r%, SL 로직)
2. **TP/트레일링 구조 최적화** → 손익비를 1:1.5~2.0로 끌어올림
3. **엔트리 필터 강화** (HTF·세션·ATR·Volume) → 허수 진입 제거
4. **레짐 인식 & 프리셋** → 레인지/트렌드별 파라 분기
5. **실행·슬리피지 캡** 튜닝 → 페이퍼에서 체결률/슬리피지 갭 최소화
6. **상관·익스포저 캡** → 실거래 포트폴리오 변동성 안정화
7. **운영 게이트(DDL/연속SL/복원)** 확정 → 라이브 이행

> **안티패턴 경고**
>
> * 승률부터 올리려다 **손익비 붕괴**
> * 백테만 최적화 → OOS 급감(**과최적화**)
> * 수수료·슬리피지 과소모델링 → 라이브 성능 붕괴

# 8) Windsurf에 바로 던질 “개발 태스크” 묶음

* [ ] **리스크 엔진**: r%/트레이드, DDL, 연속SL, 상관캡, 레버리지·청산가 여유 검사
* [ ] **슬리피지/수수료/펀딩 모델**: ATR 기반 슬리피지 + 펀딩 실현치 반영
* [ ] **레짐 태거**: 트렌드(ADX/MA slope), 변동성(ATR%), 레인지(빅핍/트루레인지 압축)
* [ ] **TP/SL/Trail 모듈**: R-multiple 기반, BE 이동, 시간 청산
* [ ] **실험 프레임**: walk-forward + 몬테카를로 자동 리포트 생성
* [ ] **실행 어댑터**: 부분체결/재시도/슬리피지 캡/상태 스냅샷
* [ ] **관제 대시보드**: PnL, 노출, 레짐, 체결에러, DDL 경보

# 9) 포지션 사이징 공식(예시; 그대로 쓰기 좋음)

* 위험액(USDT) = `Equity * r%`
* 1R(가격) = `Entry - Stop` (롱 기준; 숏은 반대)
* 수량 = `위험액 / (1R * 계약가치 환산)`
* **청산가 여유검증**: `(Entry - Liq) ≥ (liq_buffer_multiple_of_SL × 1R)`

> **Kelly-lite** (참고용, 절대 과도하게 쓰지 말 것)
> `f* = edge/odds` 근사로, 실전은 `f = f*/3` 이하로 캡.
