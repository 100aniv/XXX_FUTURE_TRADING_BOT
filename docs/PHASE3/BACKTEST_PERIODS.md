# 튜닝 전략 변경 (2025-10-26)

**⚠️ 중요: 백테스트 기반 튜닝에서 페이퍼 모드 베이지안 튜닝으로 전환**

기존 백테스트 WFA 방식은 다음 문제로 인해 **페이퍼 모드 실시간 튜닝**으로 대체:
- WFA 루프 처리 복잡도 및 일관성 문제
- 세그먼트별 거래 수 불일치
- 실제 시장 조건과의 괴리

**새로운 접근법:**
1. **페이퍼 트레이딩 환경**에서 실시간 거래 데이터 수집
2. **PostgreSQL `trading.trades` 테이블**에서 7일 롤링 메트릭 추출
3. **Optuna TPE 샘플러**로 베이지안 최적화 실행
4. 최적 파라미터를 `configs/<전략>/active.yml`에 자동 발행
5. Docker 컨테이너 재시작으로 즉시 적용

**모듈 위치:**
- 코어: `common/tuning_core.py`
- CLI: `common/tuner_cli.py`

**사용 예시:**
```bash
python -u common/tuner_cli.py \
  --strategy scalping \
  --study scalp_paper_20251026 \
  --trials 10 \
  --publish file
```

# 3) **WFA(워크-포워드) 블록 설계** 템플릿

연산 시간을 아끼면서도 과적합 방지하는 표준 안:

* **저주기(스캘핑/데이트레이드/리버전)**

  * **Train 6~12주 → OOS 2~4주**, 총 **6~8회 롤링**
  * 대표 레짐 3개(강세/약세/레인지)에서 각 2회씩

* **중/고주기(스윙/트렌드/브레이크아웃)**

  * **Train 6~12개월 → OOS 3개월**, 총 **3~4회 롤링**
  * 서로 다른 레짐 블록을 **훈련/검증에 섞지 말고** 순차 진행

* **앙상블**

  * **개별 전략 프리셋** 확정 후: **Train 3~6개월 → OOS 2개월** × **2~3회 롤링**
  * 목표 함수: **MDD↓·Ulcer↓** 가중(= 자본곡선 매끈함) + Expectancy 유지

# 4) **대표 조합(레짐 커버리지 80%+) 샘플** — *실전 권장 패키지*

> 총 OOS 등가 6~9개월 수준으로 컴퓨팅/시간 대비 효율 최대화

1. **2018-약세(12M)**: *2018-01~12* → 약세 대응(손절/리스크 엔진)
2. **2020-코로나(5M)**: *2020-02~06* → 급변/슬리피지·FlashGuard 검증 ([위키백과][3])
3. **2020-반감기~2021-강세(12M)**: *2020-05~2021-04* → 추세/트레일/익절 분할 ([Bitbo Charts][1])
4. **2022-루나/FTX(9M)**: *2022-04~12* → 시스템 스트레스/재시작 복원/체결 오류 대응 ([위키백과][4])
5. **2023-10~2024-03(ETF 기대·승인)(6M)**: 정책/자금유입 변동성 적응 ([Reuters][6])
6. **2024-04~09(4th 반감기 직후)(6M)**: 반감기 직후의 “찝찝한” 변동 구간 튜닝 ([Bitbo Charts][1])

> 위 1~6 중 **전략군별 최소 수요**에 맞춰 3~5개만 선택해 **WFA 롤링**으로 구성하면, 10년 전수와 유사한 일반화 성능을 훨씬 적은 계산량으로 확보 가능.

# 5) 실행 팁 (시간·연산 최적화)

* **단일 전략 → 단일 심볼(BTC)**에서 **Exits 먼저** 튜닝(손익비 구조 확보) → 그 프리셋으로 **ETH/ALTS 전이**.
  멀티 전략을 한꺼번에 튜닝하면 연산량 폭증 + 원인 추적 불가.
* **LHS(라틴 하이퍼큐브) 20~40샘플 + 베이지안 미세화**로 파라미터 탐색 폭 축소.
  목적함수: `OOS_Expectancy – 0.7×MDD_penalty`.
* **대표 5일 세션 샘플링**(런던/뉴욕 오픈 2주치)로 스캘핑/데이 A/B 먼저 거르고, 합격본만 전체 블록 확장.
* **수수료/슬리피지/펀딩은 과대추정**(보수적)으로 고정. 백테 대비 페이퍼 손상률 ≤ 25%를 합격선으로.

## 6-1) HTF(1h/4h) 확장 윈도우 — 장기 구간(필수)

> 중/고주기 전략은 단일 레짐 6~12개월로는 WFA 블록이 충분히 나오지 않음. 아래 장기 윈도우를 추가로 사용해 최소 블록 수를 확보하라.
 
- 1h(Swing/Breakout): Train 6~12개월 → OOS 3개월, 블록 2개 이상 권장
- 4h(Trend): Train 12개월 → OOS 3개월, 블록 2개 이상 권장
 
 추천 장기 윈도우
 
```yaml
periods_htf:
  htf_2018_2019: { start_date: '2018-01-01', end_date: '2019-12-31' }
  htf_2020_2021: { start_date: '2020-01-01', end_date: '2021-12-31' }
  htf_2022_2024: { start_date: '2022-01-01', end_date: '2024-12-31' }
```
 
사용 가이드
- 1h는 각 htf_* 윈도우에서 최소 2개 이상 WFA 블록이 생성되도록 권장(6개월+3개월 × 2회 이상)
- 4h는 htf_2022_2024(3년)에서 최소 2개 블록 확보(12개월+3개월 × 2회)
- 기존 대표 레짐 표본(periods)은 단기/저주기(5m/15m) 검증 중심, HTF는 위 장기 윈도우를 우선 사용
 
> 앙상블 OOS는 **etf_anticip_24 + halving24_post + 2025-YTD** 중 2개 블록을 권장. ETF 승인(2024-01-10)·반감기(2024-04-19/20) 등 **구조적 변화 이벤트**를 반드시 포함하라. ([Reuters][6])

## 한 줄 요약

* **전수 10년** 돌리지 마라. **레짐 대표 블록 3~5개 + WFA 롤링**으로 일반화 성능을 더 빠르게 확보한다.
* 전략별 **최소 테스트 길이**를 지키고(스캘핑=주 단위, 트렌드=연 단위), **Exits→Entries→전이→앙상블** 순서를 고수.
* 이벤트(ETF 승인, 반감기, 루나/FTX, 코로나) 포함 구간은 **OOS 필수**로 넣어야 한다. ([Reuters][6])
